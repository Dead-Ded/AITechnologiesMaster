# КТ3, Задание 1: Оценка и анализ гиперпараметров алгоритмов классификации

## Протокол (согласно принятым ранее решениям)

- **Цель:** `SeverityBin = (Severity >= 3)` (бинарная классификация).
- **Модели:** LogisticRegression (baseline), GaussianNB (байесовский), HistGradientBoostingClassifier.
- **Метод поиска:** `RandomizedSearchCV` (фиксированный seed → воспроизводимость), refit по **PR-AUC**.
- **Кросс-валидация:** `GroupKFold(5)` по `group_id` — без утечки через пространственно-временные повторы (см. анализ источников).
- **Метрики оценки конфигураций:** PR-AUC (основная), ROC-AUC, Brier, F1@0.5; отдельно отслеживается разрыв train/test (переобучение).
- **Скрипт:** `kt3/hparam_search.py`; результаты: `kt3/out/best_params.json`, `kt3/out/hparam_summary.csv`.

Запуск на полном файле:

```bash
python kt3/hparam_search.py --data <путь>/US_Accidents_March23_with_groups.csv --subsample 1000000 --n-iter-scale 1.0
```

(по умолчанию читается `kt3/df_with_groups.csv.gz`; подвыборка — равномерный шаг по времени, чтобы сохранить все эпохи и источники).

## Результаты smoke-теста (локальная подвыборка 50 тыс. строк, 2016–2017, базовая ставка 0.43)

| Модель | Лучший PR-AUC | ROC-AUC | Brier | F1 | Конфигураций | Время |
|---|---|---|---|---|---|---|
| LogReg | 0.5226 | 0.6073 | 0.2367 | 0.4231 | 9 | 8 c |
| GaussianNB | 0.5172 | 0.6028 | 0.4332 | 0.1176 | 4 | 0.6 c |
| HistGB | 0.8940 | 0.9261 | 0.1063 | 0.8382 | 16 | 25 c |

### Найденные лучшие гиперпараметры (`best_params.json`)

- **LogReg:** `C=3.0, penalty=l1, solver=liblinear, class_weight=None`
- **GaussianNB:** `var_smoothing=1e-07` (близко к дефолту 1e-9; в диапазоне 1e-7…1e-0 PR-AUC меняется на <0.001)
- **HistGB:** `learning_rate=0.1, max_leaf_nodes=31, min_samples_leaf=20, max_depth=None, l2_regularization=0.0, max_iter=200, early_stopping=True, validation_fraction=0.1`

### Анализ влияния гиперпараметров (mean test PR-AUC по значениям)

**LogReg.** Чувствительность минимальна: почти все конфигурации дают 0.522–0.523. Значим только сильный перегиб регуляризации (`C=0.01` → 0.4998, модель вырождается в константу). `class_weight='balanced'` чуть ухудшает PR-AUC (0.5132 против 0.5225) — при ставке ~0.4 этот приём смещает вероятности вверх и портит ранжирование. Вывод: линейная модель не может извлечь сигнал из лат/лонг и нелинейных взаимодействий — это её потолок, а не проблема параметров.

**GaussianNB.** Гиперпараметр практически мёртвый (разброс 0.0012): Naive Bayes упирается в предположение о независимости признаков, а не в `var_smoothing`. Отдельно бросается в глаза Brier=0.433 (против 0.237 у LogReg) — подтверждение калибровочной проблемы байесовской модели, найденной ранее; меточный F1@0.5=0.118 тоже следствие самоуверенных вероятностей. Ранжирующие метрики (PR/ROC-AUC) при этом приемлемы — как и обсуждалось, GNB годен только как baseline для ранжирования.

**HistGB.** Здесь настройка параметров реально важна:
- `min_samples_leaf` — самый сильный фактор (20 → 0.893, 100 → 0.856): на 7+ млн строк листья должны быть мелкими по относительному размеру, но не слишком;
- `learning_rate=0.1` лучше 0.03/0.05 при фиксированном `max_iter=200` (бюджет итераций не позволяет маленькому шагу сойтись);
- `max_leaf_nodes=31` оптимум (15 недообучается, 63 сильнее переобучается);
- `l2_regularization=0` достаточно благодаря `early_stopping=True`;
- разрыв train−test PR-AUC ≈ 0.08–0.09 — заметное переобучение, которое early stopping частично гасит; на полных данных ожидаемый разрыв меньше.

## Вывод

1. Порядок моделей не меняется и после тюнинга: **HistGB ≫ LogReg ≈ GaussianNB**; байесовский классификатор остаётся sanity-check baseline (его потолок задан гипотезой независимости, а не гиперпараметрами).
2. Гиперпараметрический поиск даёт наибольший выигрыш для градиентного бустинга за счёт контроля ёмкости (`min_samples_leaf`, `max_leaf_nodes`); для LogReg/GNB эффект в пределах шума фолдов (std ≈ 0.025) — их «лучшие» параметры следует считать просто устойчиво-хорошими.
3. Выбранные конфигурации сохранены в `kt3/out/best_params.json` и используются без изменений на последующих этапах эксперимента (LOSO, temporal split, калибровка).
4. Метрики подобраны корректно: refit по PR-AUC устойчив при ставке 0.43; на полном файле (ставка 0.195) PR-AUC станет ещё более дискриминирующей.

## Ограничение smoke-теста

Локальный `df_with_groups.csv.gz` содержит только первые 50 тыс. строк оригинала (2016–2017 гг., ставка 0.40 вместо 0.195), поэтому абсолютные значения метрик не переносимы на полный датасет. Протокол и кодовые выводы (иерархия факторов, нечувствительность GNB) проверены; финальные числа необходимо получить запуском на полном файле с `--subsample 1000000` или выше.
